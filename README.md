Внутреннее устройство int в Python
Иммутабельность: Тип int неизменяем. При любой математической операции (например, a += 1) старый объект в памяти не меняется — создается совершенно новый объект, и переменная начинает ссылаться на него.
Бесконечность: У int в Питоне нет предела и переполнения. Число может быть любой длины, Питон просто будет выделять под него больше памяти по мере роста.
Кэширование (оптимизация): Маленькие числа (в лекции разбираются значения до 256) заранее закэшированы в памяти. Если написать a = 1 и b = 1, они будут ссылаться на один и тот же объект (a is b выдаст True). Для чисел от 257 и выше будут создаваться разные объекты с разными id.
Большой вес: Из-за своей сложной структуры числа в Питоне довольно "тяжелые". Даже обычная единица (1) весит 28 байт.
Структура в памяти: Любое целое число под капотом состоит из 4 блоков:  Счетчик ссылок (8 байт).  Ссылка на тип объекта (8 байт).  Знак числа и его размер в системе счисления по основанию 2 в 30-й степени (8 байт).  Сами данные — "кусочки" числа, каждый из которых весит по 4 байта.

Внутреннее устройство float в Python
Иммутабельность: Как и целые числа, вещественные числа неизменяемы. Любая математическая операция создает новый объект в памяти с новым id.
Отсутствие кэширования: В отличие от маленьких целых чисел, для float нет встроенного кэша. Если написать a = 1.1 и b = 1.1 (отдельными строками), Питон создаст два независимых объекта с разными id.
Ограниченность и потеря точности: float не бесконечен. У него есть максимальное значение (около $1.79 \times 10^{308}$).
Из-за особенностей хранения в памяти возникает потеря точности: например, float(10**16 - 1) == 10**16 выдаст True, потому что "младшие" разряды просто отбрасываются.
Специальные значения: Тип float поддерживает концепцию бесконечности float('inf') и "не числа" float('nan'). При этом nan настолько особенный, что он не равен даже самому себе (nan == nan выдает False).
Строго фиксированный вес: В отличие от int, который "раздувается" по мере роста числа, любой float (даже самое гигантское значение или бесконечность) всегда весит ровно 24 байта.
Структура в памяти: Любой float под капотом состоит из 3 блоков по 8 байт:
- Счетчик ссылок (8 байт).
- Ссылка на тип объекта (8 байт).  
- Само значение числа, которое хранится в формате языка C как double (8 байт). 

Внутреннее устройство str в Python
Иммутабельность: Строки абсолютно неизменяемы. Любая попытка изменить строку (например, приклеить к ней кусок через b += " world") не меняет старый объект, а создает в памяти новую строку с новым id.
Интернирование (Оптимизация): Чтобы не плодить одинаковые тексты и экономить память, Python автоматически кэширует (интернирует) некоторые строки — обычно это короткие слова без спецсимволов. Например, a = "helloworld" и b = "helloworld" будут ссылаться на один и тот же объект.
Ручное интернирование: Если строка генерируется динамически и она огромная (например, "a" * 100500), автоматическое кэширование не сработает, и Python создаст разные объекты. Но их можно заставить ссылаться на одну память принудительно, используя sys.intern().

import sys
a = sys.intern("a" * 100500)
b = sys.intern("a" * 100500)
id(a) == id(b)

Внушительный базовый вес: Строки довольно "тяжелые" даже когда они короткие. В лекции показано, что строка "shad2024" занимает 49 байт памяти.
Структура в памяти: Строка хранит внутри себя не только текст, но и кучу метаданных. Она состоит из:  
- Счетчика ссылок (8 байт).
- Ссылки на тип объекта (8 байт).
- Длины (числа символов) строки (8 байт).
- Хэша строки (8 байт).
- Флагов и служебной информации, где как раз хранится метка об интернировании (16 байт).
- Самих символов (байтов строки), которые обязательно заканчиваются техническим "нулевым байтом" \00, как это принято в языке C (занимает от 1 байта и больше).

Внутреннее устройство контейнеров в Python
1. Списки (list)
Мутабельность: Список изменяем. Операции вроде append(), extend() или b += [2] меняют существующий объект в памяти, а не создают новый. А вот b = b + [2] создаст новый список.  
Самозацикливание: В список можно положить ссылку на него самого (a.append(a)), что приведет к бесконечной вложенности вида [[...]].  
Аллокация (запас памяти): Пустой список весит 40 байт. В памяти он хранит не только текущую длину, но и зарезервированную длину (capacity), чтобы при каждом .append() не просить у системы новую память.
Структура в памяти: Счетчик ссылок (8 байт), ссылка на тип (8 байт), текущая длина (8 байт), ссылка на массив с данными (8 байт), зарезервированная длина аллокации (8 байт). Сами элементы лежат в отдельном массиве в виде ссылок (по 8 байт на каждый элемент).  

2. Кортежи (tuple)
Иммутабельность (с подвохом): Сам кортеж неизменяем. Но если внутрь кортежа положить изменяемый объект (например, список x = ([], 1, 2)), то этот внутренний список можно менять (например, через x[0].append(1))! 
Коварный +=: Если попытаться сделать x[0] += [1], Питон честно изменит внутренний список, но потом попытается переприсвоить его обратно в кортеж и выкинет ошибку TypeError: 'tuple' object does not support item assignment. То есть данные изменятся, но программа упадет с ошибкой.
Оптимизация: Кортежи легче списков — пустой кортеж весит всего 24 байта. Кроме того, пустой кортеж () закэширован как синглтон (все пустые кортежи в программе ссылаются на одну ячейку памяти). 
Структура в памяти: У кортежа нет запаса под аллокацию (он ведь не может расти). Только счетчик ссылок, ссылка на тип, длина и сразу массив ссылок на элементы (каждая по 8 байт).

3. Множества (set)
Только хэшируемые типы: Множество — это хэш-таблица. Внутрь можно класть только неизменяемые типы (строки, числа, кортежи). Попытка положить список или другое множество вызовет TypeError: unhashable type.  
Огромный вес: Множества невероятно "прожорливы" до памяти. Даже абсолютно пустой set() весит 200 байт!  
Структура в памяти: Очень сложная. Хранит счетчик ссылок, тип, длину, число заполненных и доступных ячеек, ссылку на таблицу, хэш, и даже вшитую маленькую хэш-таблицу (на 8 записей) прямо внутри базового объекта, чтобы маленькие множества работали быстрее.

a = set()
a.add((1, 2))


4. Неизменяемые множества (frozenset)
Иммутабельный брат множества: Тот же set, но без методов изменения (нет .add(), .pop() и т.д.).
При операциях объединения (|) создает новый объект.  Его вес в памяти точно такой же, как у обычного множества (пустой весит 200 байт). Поскольку он сам неизменяем, frozenset можно класть внутрь других множеств или использовать как ключ словаря. 

a = frozenset([1, 2, 3])
b = frozenset([3, 4, 5])
a - b, b - a
a | b, a & b



5. Словари (dict)
Изменение размера в цикле: Главное правило — никогда не удаляйте и не добавляйте ключи в словарь, пока итерируетесь по нему циклом for k in d:. Это приведет к немедленной ошибке RuntimeError: dictionary changed size during iteration.  
Ключи: Те же требования, что и у set — ключом может быть только хэшируемый (неизменяемый) объект. {[1, 2]: 3} выкинет ошибку.  
Оптимизация: Начиная с версии Python 3.6+, словари внутри переписали. Теперь они используют плотный массив значений и отдельный массив индексов. Это сделало их легче (очищенный словарь весит 48 байт) и заставило словари запоминать порядок добавления ключей.

Шпаргалка по heapq
Главная суть (Min-Heap): Это структура данных, которая организует элементы массива так, чтобы самый маленький элемент всегда лежал на поверхности (под индексом 0).  Базовые операции:
heapq.heappush(a, value) — добавить элемент в кучу. Питон сам перестроит массив так, чтобы минимум остался спереди.  
heapq.heappop(a) — достать (и удалить) самый маленький элемент. В лекции наглядно показано: если закинуть в кучу числа вразнобой, а потом в цикле делать heappop, они будут выходить строго по возрастанию: -1, 0, 1, 2, 4.  
Ограничение размера (heapreplace): Если тебе нужно хранить только Топ-3 самых больших числа, можно закидывать новые элементы через heapreplace(a, value). Эта команда за один шаг выкидывает самый маленький элемент из твоего Топ-3 и ставит на его место новый, сохраняя размер кучи неизменным. 
Суперспособность (Топ-K элементов): В heapq есть готовые и очень мощные функции nlargest (найти несколько максимальных) и nsmallest (найти несколько минимальных). Пример: heapq.nlargest(3, a) мгновенно вернет три самых больших числа из списка.  
Используй heapq, когда нужно быстро найти минимум/максимум списка или найти k самых больших элементов без полной сортировки массива

Хоть Python и берет управление памятью на себя, делая разработку безопасной, с помощью модуля ctypes можно "выстрелить себе в ногу" и сломать программу на самом низком уровне.
